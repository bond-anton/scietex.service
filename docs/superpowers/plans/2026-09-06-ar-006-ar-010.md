# AR-006 + AR-010 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix two architecture-review correctness findings in `scietex.service` v2.0.0: (AR-006) make `ValkeyWorker.connect()` set/clear `_client` only on verified success so a half-connected worker cannot enter `RUNNING`, and (AR-010) close the error-boundary leaks in `AsyncTaskProcessor` — convert the empty-task case into an error `TaskResult`, consume every created task's exception, and propagate handler-startup failures into `initialize()`.

**Architecture:** AR-006 is scoped to the in-repo half of the finding. The external `scietex.logging` `AsyncValkeyHandler` **fully owns** its own `GlideClient` lifecycle (`_worker()` calls `self.connect()`/`self.disconnect()`, which hardcode `GlideClient.create`/`client.close()` — verified in `~/Projects/scietex.logging/src/scietex/logging/valkey_handler.py:103-143` and `message_broker_handler.py:153-228`). There is no injection seam to share a client, so single-client consolidation would require changing the external package (out of scope). The fix therefore makes `connect()` a reliable connectivity signal: `_client` is assigned only after `PING` succeeds and is cleared on any failure. AR-010 is three independent in-repo correctness fixes in `AsyncTaskProcessor`: the empty-task path returns an error `TaskResult` instead of raising, `handle_task` consumes the result and never lets an exception escape into an unawaited task, and `_start_task_handler` reports failure so `initialize()` returns `False` (failing fast via the existing `_startup` guard).

**Tech Stack:** Python 3.10+, asyncio, `msgspec`, optional `valkey-glide`, `scietex.logging>=1.1.0`.

**Spec:** Findings AR-006 and AR-010 in `docs/reviews/architecture/2026-09-04.md` (lines 307-341 and 442-476) and the re-prioritization in `docs/reviews/architecture/2026-09-05.md` (lines 179-197). This plan argues from those findings; executors should read both review files.

## Design Decisions (recommended)

1. **AR-006 scope: in-repo connect-state fix only.** The external `AsyncValkeyHandler` owns its `GlideClient` with no injection seam (verified against `~/Projects/scietex.logging`). Single-client consolidation is impossible without changing the external package, which is out of scope and gated on the review's Open Question 4. The in-repo fix makes `connect()` a truthful signal and centralizes the worker-side teardown ordering (`disconnect()` already clears `_client`; `cleanup()` already calls `disconnect()`). This is the pragmatic, dependency-free half of the recommendation.

2. **`connect()` assigns `_client` only after a successful `PING`.** Current code assigns `self._client = await GlideClient.create(...)` (line 207) *before* pinging, so a failed ping leaves a non-None client that `initialize()`'s `if not self.client` guard (line 283) treats as success. New flow: create into a local, ping it, and only on success assign `self._client = client`; on any failure close the local client (best-effort) and leave `_client` as `None`. This also fixes the reconnect short-circuit: today a failed ping leaves `_client` set, so a later `connect()` (e.g. from `fetch_tasks`'s reconnect at lines 449-452) early-returns `True` at line 217 without ever reconnecting.

3. **AR-010 empty-task → error `TaskResult`.** `process_task` currently raises `ValueError` for an empty `task` field (line 462). Convert it to return `TaskResult(status="error", error="Task data must contain 'task' field")`, matching the existing centralized error→`TaskResult` pattern used for "no handler found" (line 471). Remove the `Raises: ValueError` docstring note.

4. **`handle_task` consumes the result and never leaks an exception.** `handle_task` (lines 489-494) currently does `await self.process_task(...)` in a bare `try/finally`, discarding the result. If `process_task` raised, the exception escaped into the asyncio task created at line 499, which is never awaited except via cancellation → "Task exception was never retrieved". After Decision 3, `process_task` no longer raises on the empty-task path, but a defensive `except Exception` in `handle_task` that logs and converts to an error `TaskResult` guarantees no exception can escape into an unawaited task regardless of future `process_task` changes. The `finally` (pop + `task_done`) stays.

5. **`_start_task_handler` reports failure; `initialize()` propagates it.** `_start_task_handler` (lines 300-322) catches `TimeoutError` and logs but returns `None`, so `initialize()` (lines 383-395) always returns `True`. Change `_start_task_handler` to return `bool` (True on success, False on timeout or any start exception), and have `initialize()` return `False` if any handler fails to start. `_startup` (basic_async_worker.py:773-774) already raises `RuntimeError("Initialization failed")` on a `False` return, so the worker fails fast instead of reporting `RUNNING` with a handler that never became ready. The `add_task_handler` fire-and-forget call site (line 298) and `remove_task_handler`'s `_stop_task_handler` are unaffected (they ignore the return value).

6. **Tests.** Add: (a) `test_connect_ping_failure_clears_client` and `test_connect_create_failure_leaves_client_none` in `tests/test_valkey_worker.py`; (b) `test_process_task_empty_task_returns_error_result` in `tests/test_async_task_processor.py`; (c) a handler-start-failure test asserting `initialize()` returns `False`. All use the existing `DummyClient`/`monkeypatch` patterns.

```python
    async def connect(self) -> bool:
        """Establish an asynchronous connection to the Valkey server.

        Creates a new :class:`~glide.GlideClient` using the configured
        ``_client_config`` and verifies connectivity with ``PING``.

        ``_client`` is assigned only after ``PING`` succeeds, so a failed
        create or ping leaves ``_client`` as ``None`` and ``connect()``
        returns ``False``. This keeps the return value a reliable
        connectivity signal: callers that guard on ``self.client`` (e.g.
        ``initialize``) never see a half-connected worker.

        Returns:
            ``True`` if the connection is established and ``PING``
            succeeds; ``False`` on connection failure or timeout.
        """
        if self._client is not None:
            return True
        try:
            client = await GlideClient.create(self._client_config)
        except (GlideConnectionError, GlideTimeoutError):
            print("Error connecting to Valkey")
            return False
        try:
            if await client.ping():
                self._client = client
                self.logger.log(logging.INFO, "Connected to Valkey")
                return True
            print("Error pinging Valkey")
        except (GlideConnectionError, GlideTimeoutError):
            print("Error connecting to Valkey")
        # Ping failed or raised: never leave a half-connected client behind.
        try:
            await client.close()
        except Exception:
            pass  # best-effort close; the client is unusable either way
        return False
```

Note: the `except Exception: pass` on the best-effort `close()` is intentional — a failed ping means the transport is already unusable, and a close error must not mask the `False` return. Do not remove it.

class ExplodingSupportsHandler(TaskHandler):
    async def handle(self, task_data: TaskData) -> TaskResult:
        return TaskResult(status="success", error="No error")

    @property
    def supported_tasks(self) -> list[str]:
        return ["exploding"]

    def supports(self, task_type: str) -> bool:
        raise RuntimeError("supports() exploded")


@pytest.mark.asyncio
async def test_task_manager_consumes_handler_exception_without_leaking():
    """An exception raised outside process_task's try/except (e.g. in a
    handler's supports()) must be caught by handle_task so it does not surface
    as an unretrieved task exception (AR-010)."""
    import gc

    loop = asyncio.get_running_loop()
    leaked: list[str] = []
    old_handler = loop.get_exception_handler()
    loop.set_exception_handler(lambda _loop, ctx: leaked.append(str(ctx.get("message", ""))))
    proc = DemoProcessor()
    proc.add_task_handler("exploding", ExplodingSupportsHandler)
    await proc.start()
    try:
        t_id = uuid4()
        await proc.task_queue.put((t_id, TaskData(task="exploding", payload=b"{}")))
        # Give task_manager time to pick it up and finish handle_task.
        for _ in range(50):
            if t_id not in proc.running_tasks:
                break
            await asyncio.sleep(0.05)
        # Force GC so any unretrieved task exception is reported deterministically.
        gc.collect()
        await asyncio.sleep(0.05)
        assert not any("never retrieved" in m for m in leaked), f"leaked: {leaked}"
    finally:
        loop.set_exception_handler(old_handler)
        await proc.stop()
```

    async def _start_task_handler(self, handler_name) -> bool:
        """Start a registered task handler and initialize it.

        Creates an instance of the handler class, stores it in the
        active handlers dictionary, and calls its ``start()`` method
        with a timeout.

        Args:
            handler_name: The name of the handler to start.

        Returns:
            ``True`` if the handler started and became ready; ``False``
            if it timed out, raised, or was not registered.
        """
        if handler_name in self.__task_handlers:
            self.logger.log(logging.DEBUG, "Task handler %s is already started", handler_name)
            return True
        if handler_name not in self.__task_handlers_map:
            self.logger.log(logging.DEBUG, "Task handler %s not found", handler_name)
            return False
        handler_class = self.__task_handlers_map[handler_name]
        handler_instance = handler_class(handler_name, self)
        self.__task_handlers[handler_name] = handler_instance
        try:
            await asyncio.wait_for(self.__task_handlers[handler_name].start(), timeout=self.task_handler_start_timeout)
        except asyncio.TimeoutError:
            self.logger.log(logging.ERROR, "Timeout while starting Task handler %s", handler_name)
            return False
        except Exception as exc:
            self.logger.log(logging.ERROR, "Failed to start Task handler %s: %s", handler_name, exc)
            return False
        return True
```
