# AR-022 v4 — Class-only Task Registration + Error-Policy Enforcement

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement both halves of AR-022 on `main` (v4.0.0): (1) make `add_task_handler` take only a handler class with a class-name-derived lifecycle key, and (2) make the framework execute a single retry per task driven by `TaskResult.retryable`, dropping the redundant `requeue`/`retry_count` fields and flipping the raise-path default to permanent.

**Architecture:** Two independent, breaking changes to the task-handler subsystem. Half 1 reconciles registration with dispatch by removing the user-supplied `handler_name` key and `supported_tasks` override; the lifecycle key becomes `handler_class.__name__` and duplicate class registration raises. Half 2 makes the previously-inert error taxonomy actionable: `handle_task` requeues a `retryable=True` error result via `return_task_to_queue` before acking the transport entry, and treats a handler that raises as permanent. Both halves are main-only breaking changes (version already 4.0.0).

**Tech Stack:** Python 3.10+, `msgspec` (frozen `Struct` schemas), `asyncio`, `pytest-asyncio`, `ruff`, `ty`, `glide` (Valkey, optional).

**Spec:** `docs/ROADMAP.md` — v4 entries 2 ("Task registration reconciled with task types", lines 32-53) and 3 ("Error-policy enforcement on task results", lines 55-86). The plan argues from these decisions; executors read both.

```python
    def add_task_handler(self, handler_class: type[TaskHandler]) -> None:
        """Register a task handler class.

        The handler class is stored in the internal map under its class name
        (``handler_class.__name__``), which is the lifecycle key. Dispatch is
        driven by ``_find_task_handler``, which selects handlers by their
        ``supported_tasks`` membership — the class-level declaration is the
        dispatch contract, not an argument. A single instance per class is
        created on start; registering the same class twice raises.

        Args:
            handler_class: The ``TaskHandler`` subclass to register.

        Raises:
            ValueError: If ``handler_class`` is already registered.
        """
        handler_name = handler_class.__name__
        if handler_name in self.__task_handlers_map:
            raise ValueError(f"Task handler {handler_name!r} is already registered")
        self.__task_handlers_map[handler_name] = handler_class
        self.logger.log(logging.INFO, "Added Task handler: %s", handler_name)
        if self.state in (ServiceStatus.RUNNING, ServiceStatus.STARTING):
            asyncio.create_task(self._start_task_handler(handler_name))
```

## Task 4: Half 2 — Raise-path default flips to permanent + `handle_task` executes retry-once

**Files:**
- Modify: `src/scietex/service/async_tasks_processor.py:544-593` (`process_task` raise path + docstring), `:608-649` (`handle_task` requeue-before-ack), `:685-702` (`watchdog` docstring — stale "future work" note).
- Test: `tests/test_async_task_processor.py`.

**Interfaces:**
- Consumes: `TaskResult` (now without `retry_count`/`requeue`), `return_task_to_queue(task_id, task_data)`, `on_task_completed(task_id, task_data, task_result)`.
- Produces: `process_task` returns `TaskResult(status="error", error=str(e))` (retryable defaults False) when a handler raises. `handle_task` requeues a `status="error"` + `retryable=True` result via `return_task_to_queue` BEFORE calling `on_task_completed` (XADD then XACK). Permanent errors (`retryable=False`) are acked+dropped (no requeue).

**Design notes (from ROADMAP entry 3):**
- The requeue decision goes in `handle_task` (which has the final `result` in scope), BEFORE `on_task_completed` in the `finally` block. Order: on a retryable error, call `await self.return_task_to_queue(t_id, t_data)` first, then let the `finally` ack via `on_task_completed`. This yields XADD-then-XACK, preserving at-least-once without duplication.
- The requeue must happen only for `status == "error"` AND `retryable is True`. Success results and permanent errors are not requeued.
- The requeue call must be wrapped so a requeue failure does not crash `handle_task` (mirror the existing defensive pattern around `on_task_completed` at 639-649). If requeue fails, the task is still acked (dropped) — log the failure. (The transport entry is acked regardless; a failed XADD means the retry copy is lost, which is acceptable and logged.)
- `process_task` raise path (line 588): change `TaskResult(status="error", error=str(e), retryable=True)` → `TaskResult(status="error", error=str(e))`. Update the surrounding comment (584-587) and the method docstring (552-557).
- The `watchdog` docstring (693-702) says error-path requeue is "future work gated on result availability". That is now implemented — rewrite the note to state that error-path requeue is handled in `handle_task` and the watchdog handles only timeout-driven requeue via `timeout_action`.
